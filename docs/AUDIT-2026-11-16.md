## 1. Security & auth

### 🔴 1.1 Default admin credentials are `admin` / `admin`
`server/_core/env.ts:10-11`
```ts
adminUsername: process.env.ADMIN_USERNAME ?? "admin",
adminPassword: process.env.ADMIN_PASSWORD ?? "admin",
```
`api/login.ts:19` checks `if (!adminPassword || !adminUsername)` to catch missing config, but because of the fallbacks those values are never empty. If `ADMIN_USERNAME`/`ADMIN_PASSWORD` are ever missing in a Vercel environment (including Preview deployments), anyone can log in with `admin/admin` and get full CMS, media and lead access.
**Fix:** remove the fallbacks (`?? ""`), and confirm both vars are set in **every** Vercel environment.

### 🔴 1.2 Logout doesn't log you out
Login sets cookie `auth_token` (`api/login.ts:58`); auth reads `auth_token` (`server/_core/context.ts:24`); but `auth.logout` clears **`app_session_id`** (`server/routers.ts:20-27`, `shared/const.ts:1`). The session cookie survives logout for its full 24h. `server/auth.logout.test.ts` asserts the wrong cookie name, so the test passes and hides the bug.
**Fix:** use one constant for the cookie name everywhere and expire `auth_token` on logout.

### 🟠 1.3 No brute-force protection on `/api/login`
There's no rate limit, lockout or delay, and the comparison isn't constant-time (`username !== … || password !== …`). `express-rate-limit` is installed but unused (it's Express middleware and won't work in a Vercel function anyway).
**Fix:** use Vercel Firewall rate limiting on `/api/login` (or Upstash/KV counter), add `crypto.timingSafeEqual`, and store a bcrypt hash instead of a plaintext password env var (`bcrypt` is already a dependency).

### 🟠 1.4 JWT returned in the JSON body
`api/login.ts:59` returns `{ token: jwtToken }` even though the cookie is `HttpOnly`. That puts the token in JS-readable memory, so any XSS can steal it, and nothing on the client uses it. Also `Max-Age=86400` is hard-coded and ignores `JWT_EXPIRY`.
**Fix:** drop `token` from the response; derive `Max-Age` from the same expiry.

### 🟠 1.5 Draft content is publicly readable
- `blogs.getBySlug` (`server/blogRouter.ts:30`) returns unpublished posts to anyone who knows or guesses the slug.
- `projects.getById` / `projects.getBySlug` (`server/projectRouter.ts:23-41`) return `draft`/`scheduled` projects.
- `injectDynamicSEO` (`server/_core/seoInjector.ts`) also leaks draft titles/descriptions into HTML.
**Fix:** filter by `published` / `status = 'published'` unless `ctx.user?.role === 'admin'`.

### 🟡 1.6 `SameSite=None` on the admin cookie
`server/_core/cookies.ts:23` sets `SameSite=None` whenever HTTPS. The admin and API share one origin, so there's no reason for it. It sends the admin cookie on cross-site requests, which widens CSRF exposure on tRPC mutations.
**Fix:** use `SameSite=Lax` (or `Strict`) always.

### 🟡 1.7 Inconsistent authorization on blog mutations
Blog `create/update/delete` use `protectedProcedure` (any valid JWT) while every other admin write uses `adminProcedure`. `blogs.list` treats any logged-in user as admin (`isAdmin = !!ctx.user`). Today only admin JWTs exist, so this isn't exploitable yet, but it's one change away from being a hole.

### 🟡 1.8 SEO injector trusts the `Host` header and doesn't escape output
`api/seo-injector.ts:7-12` builds the fetch URL from `x-forwarded-host`/`host`, and the result is CDN-cached (`s-maxage=60`), which creates a host-header / cache-poisoning risk. `seoInjector.ts` interpolates DB strings into HTML attributes unescaped (a `"` in a title breaks the markup; `$&`/`$1` sequences are interpreted by `String.replace`).
**Fix:** hard-code `https://www.gokulkp.com` (or read `dist/index.html` from disk), HTML-escape values, and use a replacer function.

### 🟡 1.9 Media upload has no validation, and won't work on Vercel
`server/mediaRouter.ts:19-58`: there's no size limit and no MIME allow-list, and the extension comes from the client file name (`.html`/`.svg` would be accepted). It writes to `public/uploads` on the local filesystem, which is **read-only/ephemeral on Vercel**, so uploads fail or vanish in production. `addExternal` accepts any string as URL (including `javascript:`).
**Fix:** move uploads to Vercel Blob / Cloudinary (you already use Cloudinary), allow-list image/video/pdf types, cap size, validate URLs with `z.string().url()` + `https:` check.

### 🟡 1.10 Contact form spam protection is client-trusted
`clientTimestamp` comes from the browser, so bots just send an old timestamp. There's no server-side rate limit, and `contact.list` is unpaginated.
**Fix:** add Vercel Firewall rate limit / Turnstile, cap per-IP submissions.

### ⚪ 1.11 Smaller items
- `context.ts:25` cookie parsing uses `includes("auth_token=")`, which also matches e.g. `xauth_token=`. Use the `cookie` package (already installed).
- CSP allows `'unsafe-eval'` and `'unsafe-inline'` scripts. `unsafe-eval` is likely unnecessary.
- `main.tsx` redirects to `getLoginUrl()` (old Manus OAuth) on `UNAUTHORIZED`; `VITE_OAUTH_PORTAL_URL` isn't set, so `new URL("undefined/app-auth")` throws.

## 2. Functional bugs

### 🟠 2.1 Lead notifications almost certainly never arrive
`contact.submit` calls `notifyOwner()` (`server/_core/notification.ts`), which posts to the **Manus "forge" API** (`BUILT_IN_FORGE_API_URL`/`KEY`), a leftover from the Manus template. If those aren't set it throws, and the error is swallowed and logged as `info`. Leads only show up if you check `/admin/contact`.
**Fix:** send email via Resend/Postmark, or a WhatsApp/Telegram/Slack webhook. For a lead-gen portfolio, this is the most important thing to fix.

### 🟠 2.2 Conversion tracking events go nowhere
`client/src/utils/analytics.ts` sends every event (`form_submit_success`, `whatsapp_click`, `email_click`, …) to **Umami** (`window.umami`), but no Umami script is loaded (`.env.example` still has `analytics.example.com` placeholders). GA4/GTM never receive form or WhatsApp conversions.
**Fix:** push to `window.dataLayer` / `gtag('event', …)` instead.

### 🟠 2.3 CSP blocks GA4 collection in many regions
`vercel.json` `connect-src` lists `www.google-analytics.com` and `analytics.google.com` only. GA4 commonly sends hits to `region1.google-analytics.com` and other `*.google-analytics.com` / `*.analytics.google.com` hosts, so those hits get blocked.
**Fix:** use `https://*.google-analytics.com https://*.analytics.google.com https://*.googletagmanager.com` in `connect-src` and `img-src`, then verify in GA4 DebugView.

### 🟡 2.4 GA4 may double-count
`client/index.html` loads both GTM (`GTM-NNXPGFLC`) **and** a direct `gtag('config','G-JB54FDS086')`. If the GTM container also has a GA4 Configuration/Google tag for the same ID, every pageview is counted twice. Check in GTM and keep only one.

### 🟡 2.5 Public read endpoint writes to the DB
`content.get` (`server/contentRouter.ts:7-20`) inserts a row if missing, and it's called by the **Footer on every page**. That means one serverless call plus a DB round trip per pageview, and a write on a public GET.

### 🟡 2.6 Blog view counter is racy and may be dropped
`blogRouter.ts:40` does a read-modify-write and doesn't await it. In serverless the function can freeze before it runs. Use `sql\`${blogs.views} + 1\`` and `await` it.

### 🟡 2.7 Broken Docker / start scripts
`Dockerfile` CMD runs `pnpm run start:server`, which doesn't exist. `pnpm start`/`pnpm dev` run `vercel dev` (Vercel CLI isn't a dependency). Either fix them or delete the Dockerfile.

### 🟡 2.8 The test suite hits a real database
`server/contact.submit.test.ts` inserts into whatever `DATABASE_URL` points at. With a local `.env` pointing at Turso production, **running the tests writes fake leads into the production DB**. Without one, it fails (`no such table`). Mock `db` or use an in-memory libsql DB with migrations.

## 3. SEO

### 🟠 3.1 Prerendered pages all have the home page's body
`scripts/prerender.js` only swaps `<title>`/meta/canonical. Every prerendered route ships the **same `<body>` fallback** from `client/index.html`: home H1, home intro and the same image. Crawlers or link previews that don't execute JS see 16 near-duplicate pages.
**Fix:** real SSG (e.g. `vite-react-ssg`, or render each route with `react-dom/server`), or at minimum per-route H1 and intro text in the prerender config.

### 🟠 3.2 Dynamic pages get the home canonical
`/blogs/*`, `/portfolio/*/*` and DB-driven `/marketing/*` are rewritten to `api/seo-injector`, which fetches `/index.html`. That is the prerendered **home** page, with `<link rel="canonical" href="https://www.gokulkp.com">`. The injector doesn't replace canonical or `og:url`. After hydration, Helmet adds a **second** canonical, so Google sees two conflicting ones.
Also, the injector's regex targets `<meta name="twitter:title">` but the HTML uses `property="twitter:title"`, so Twitter tags never update.

### 🟠 3.3 Duplicate tags after hydration
`SEO.tsx` (react-helmet-async) **adds** title/description/og/twitter/robots/canonical tags but doesn't remove the static ones in `index.html` / prerendered HTML. Rendered pages end up with duplicate `description`, `og:*`, `robots` and `canonical` tags. Fix: mark static tags with `data-rh="true"` so Helmet takes them over, or strip them in prerender and let one system own them.

### 🟡 3.4 Duplicate PrepMeal URLs
`/marketing/prepmeal`, `/marketing/prepmeal-growth` and `/marketing/prepmeal-launch` all render the same component (`App.tsx:113-115`). `prepmeal-launch` is prerendered with a **self-referencing canonical**, and `PrepmealCaseStudy.tsx` has no `<SEO>` component at all, so client-side navigation also keeps the previous page's title.
**Fix:** 301 the two aliases to `/marketing/prepmeal` in `vercel.json` and add `<SEO>` to the page.

### 🟡 3.5 Sitemap: the dynamic version is dead code
`client/public/sitemap.xml` exists as a static file. Vercel serves filesystem files **before** rewrites, so the `/sitemap.xml → /api/sitemap` rewrite never runs. The static file is missing `/marketing/aureum-asset-management` (which is prerendered and indexable) and any DB blogs/projects. Pick one: delete the static file, or delete `api/sitemap.ts` and keep the static one up to date.

### 🟡 3.6 Soft 404s
The catch-all rewrite returns `index.html` with **HTTP 200** for any URL. `NotFound` sets `noindex`, but only after JS runs. Unknown `/marketing/*`, `/blogs/*` and `/portfolio/*` paths also return 200 from the injector.

### ⚪ 3.7 Smaller items
- `client/index.html` fallback uses `<header className="sr-only">`. That's JSX, not HTML, so the header nav is **visible** to non-JS readers and the class does nothing. Use `class`.
- Its fallback nav links to `/portfolio/video` and `/portfolio/photo`, which are 301 redirects. Link to `/video` and `/photo`.
- The `meta keywords` value is long and stuffed ("best digital marketer in dubai…"). Google ignores the tag and it reads as spammy. Remove it.
- JSON-LD `Organization` + `ProfessionalService` + `Person` all describe you. Consider linking them with `@id` so Google sees one entity.

## 6. Performance

### 🟠 6.1 Images aren't served in modern formats, and almost none are lazy-loaded
- WebP versions exist for most brand images, but code references **284 `.jpg` + 61 `.png` vs 52 `.webp`**.
- 104 JPG/PNG files over 500 KB in `client/public` (~118 MB total). Examples: `aureum/slide-7.png` 2.9 MB, `Little-Rooster/paperbag-nobg.png` 2.5 MB.
- Only **9 of 103 `<img>`** tags use `loading="lazy"`, and few set `width`/`height`, which causes CLS.
- **Fix:** point references at the `.webp` files (or use `<picture>`), add `loading="lazy" decoding="async"` below the fold, and set dimensions. `scripts/optimize-images.js` exists, so run it on the remaining PNGs.

### 🟡 6.2 Forced loader overlay
`client/index.html` covers the page with a full-screen loader until React mounts (fallback after 1.5 s). It hides the prerendered HTML, delays LCP and makes the prerender pointless for users. Remove it or only show it after ~300 ms without content.

### 🟡 6.3 JS weight
The main entry chunk is 408 KB (128 KB gz), plus `vendor-framer` 133 KB preloaded on every page. Three.js (489 KB) is split, which is good. The global `CustomCursor`, `ScrollProgress`, grain overlay and the IntersectionObserver re-scan on every route change add main-thread work on mobile. Consider disabling the custom cursor on touch devices and when `prefers-reduced-motion` is set.

### ⚪ 6.4 Duplicate video
`aquacare-shower-filter-reel.mp4` (6 MB) is committed twice: in `client/public/…` and in root `public/…`.

- Star ratings render as bare `★` characters with no accessible label.
- Several heading levels come from animated `RevealText`. Make sure the real text, not split spans, is what screen readers get.

## 8. Repository hygiene & dependencies

### 🟡 8.1 Unused template code (Manus scaffold)
- **Server:** `server/_core/{sdk,llm,imageGeneration,voiceTranscription,dataApi,map}.ts`, `server/storage.ts`.
- **Client:** `AIChatBox.tsx`, `Map.tsx`, `ManusDialog.tsx`, `DashboardLayout*.tsx`, most of `const.ts`.
- **Other:** `update_routers_logout.py`, `ANTIGRAVITY_AI_PROMPT.md`, `todo.md` (it's in `.gitignore` but still tracked), and the second `client/vercel.json` (ignored by Vercel but confusing).

### 🟡 8.2 Unused dependencies driving most audit findings
These have no imports in `client/`, `server/`, `api/` or `scripts/`: `openai`, `mysql2`, `bcrypt`, `express-rate-limit`, `cors`, `@aws-sdk/*`, `nanoid`, `vite-plugin-manus-runtime`, `@builder.io/vite-plugin-jsx-loc`, `@react-three/drei`, and the devDependency `add`. `express`, `jose`, `axios` and `better-sqlite3` are only used by the dead `sdk.ts`/scripts.
Removing them clears most of the 196 advisories. Upgrade the ones that are actually used: `@trpc/server`, `drizzle-orm`, `zod` and `vite` all have open high advisories.

### 🟡 8.3 Repo size
`.git` is 244 MB and `client/public` is 284 MB. The root `public/` folder (42 MB) isn't Vite's `publicDir`, so it's never deployed. It holds a **34 MB PDF** and two other uploads in `public/uploads/`. Delete the root `public/`, and move large media (PDF decks, MP4s) to Cloudinary/Blob.

### ⚪ 8.4 Code quality
37 `any` casts (e.g. `ctx.user` is a JWT payload cast to the DB `User` type). There's no ESLint config and no CI workflow running `check`/`test`/`build` on PRs.
